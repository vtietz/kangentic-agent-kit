# Follow-ups and skill proposals

## Product follow-up

Only after explicit instruction, search the profile backlog and GitHub issues by
key terms. Report search terms and results. A backlog match requires asking
whether to revive it; an open issue receives the follow-up there; a closed issue
requires reporting its closure reason before refiling.

When no match exists, create one GitHub issue with a short noun-phrase title and
a body containing the human's words, why it is outside the current card, and the
current card title plus shipping commit. Record its URL under card `##
Follow-ups`. Do not claim it is on the board; importing remains a separate act.

## Skill proposal

Only after explicit `file skill proposal`, read Review's validated candidate and
search board/backlog by capability and trigger. Link duplicates. Otherwise
create one Backlog task labeled `skill-proposal` with trigger, evidence/sources,
existing docs/skills to update, reusable capability, exclusions, realistic
validation task, and origin card/SHA. Do not implement the skill in this session.
